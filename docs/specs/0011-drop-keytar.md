# 0011 — Drop keytar; tokens.json is the sole persistent token store

**Run:** 2026-04-26-0747-drop-keytar
**Tier:** Yellow (authorized; touches auth flow)
**Branch:** `chore/drop-keytar`
**Changeset bump:** minor

## Problem

`keytar@7.9.0` is orphaned (last release 2022; Electron deprecated 2023) and its transitive
`prebuild-install@7.1.3` prints `npm warn deprecated prebuild-install@7.1.3: No longer
maintained.` on every install. It is also the *only* native binding in our dep tree —
removing it eliminates a Windows/Linux install reliability cliff.

The agent-first design already treats env vars (`FREELO_API_KEY` + `FREELO_EMAIL`) as the
recommended path. The OS keychain has always been the niche tier. Existing keychain users
re-run `freelo auth login` once after upgrade and land in `tokens.json` (mode 0600).

## Proposal

Remove `keytar` from the dep tree. `tokens.json` (in `getConfDir()`, mode 0600) is the
sole persistent credential store. `FREELO_NO_KEYCHAIN` is **deleted** (no-op was rejected
— clean break, one less env-var doc surface).

## API surface

None. This is a local-only refactor with the public envelope schemas
(`freelo.auth.login/v1`, `freelo.auth.logout/v1`, `freelo.auth.whoami/v1`) unchanged.

## Data model

```
~/.config/freelo-cli/  (XDG; platform-specific via `conf`)
├── config.json        ← profiles + defaults, owned by `conf`
└── tokens.json        ← { [profile]: apiKey }, mode 0600
```

After this change there is no `freelo-cli` entry in any OS keychain on first install.
Existing entries from prior versions persist harmlessly.

## Edge cases

1. **Existing keychain user upgrades.** Their token in OS keychain becomes inaccessible
   after upgrade. The first command that needs the token throws
   `ConfigError({ kind: 'missing-token' })` → exit 3 with `AUTH_MISSING`. They re-run
   `freelo auth login`; new credentials land in `tokens.json`. Old keychain entry
   persists in OS keychain (Mac Keychain Access, Windows Credential Manager, libsecret) —
   we do **not** clean it up. CHANGELOG calls this out.
2. **`FREELO_NO_KEYCHAIN=1` set in user's environment after upgrade.** Becomes a no-op.
   We do **not** error on it; the var is simply unrecognized. (Decision log entry: keep
   silent rather than warn — env-vars-as-no-ops is the conventional CLI pattern.)
3. **Concurrent `tokens.json` writes.** Same risk as before — `writeFile` is not atomic
   across processes. Out of scope (not a regression).
4. **Windows file mode.** `chmod 0600` is a no-op on Windows; the existing `try/catch` in
   `writeTokensFile` already swallows the failure. No change.
5. **Partial keychain entry from prior install.** A user who had keychain-only credentials
   sees `auth whoami` exit 3 (`AUTH_MISSING`) instead of returning the cached identity.
   This *is* the documented breaking change.

## Non-goals

- No `@napi-rs/keyring` or other keychain replacement (Option C, decided).
- No automatic keychain cleanup on upgrade (out of scope; users can remove manually).
- No Windows Credential Manager / DPAPI / libsecret special handling.
- No `tokens.json` encryption-at-rest. Mode 0600 is the security boundary.
- No transitional migration / dual-write phase. Hard cut, decided.
- No CI guard `pnpm ls keytar` — recommended but deferred. The lockfile diff and the
  test-suite removal of all keytar mocks together provide regression coverage.

## Open questions

None. All architectural calls (delete `FREELO_NO_KEYCHAIN` checks, hard cut migration,
no replacement library, minor bump) were made by the user up-front per the run brief.

### Commit 1 — `refactor(config): tokens.json is the sole persistent token store`

Source + tests of the `src/config/` and `src/commands/auth/` layer.

- `src/config/tokens.ts` — collapse to file-only. Drop `KeytarApi`, `tryKeytar`,
  `_resetKeytarState`, `keytarUnavailable`, `fallbackWarningEmitted`,
  `emitFallbackWarning`. Body becomes:

  ```ts
  export async function readToken(profile: string): Promise<string | null> {
    const tokens = await readTokensFile();
    return tokens[profile] ?? null;
  }
  export async function writeToken(profile: string, apiKey: string): Promise<void> {
    const tokens = await readTokensFile();
    tokens[profile] = apiKey;
    await writeTokensFile(tokens);
  }
  export async function deleteToken(profile: string): Promise<void> {
    try {
      const tokens = await readTokensFile();
      if (profile in tokens) {
        delete tokens[profile];
        await writeTokensFile(tokens);
      }
    } catch { /* file may not exist */ }
  }
  ```

  Drop the optional `opts` parameter on `writeToken` (was only used to gate the
  fallback-warning) — call sites updated below.
