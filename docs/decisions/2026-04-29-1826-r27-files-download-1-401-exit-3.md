# Decision 1 — 401 maps to exit 3 (AUTH_EXPIRED), not 4

**Run:** 2026-04-29-1826-r27-files-download
**Phase:** test (test-writer / orchestrator)
**Agent:** orchestrator

**Question:** Spec 0039 §6 listed `401 → FreeloApiError exit 4 (AUTH_REQUIRED)`. The actual implementation in `FreeloApiError.fromResponse` maps 401 → `AUTH_EXPIRED` with `exitCode: 3`. Which is canonical?

**Decision:** Exit 3 (`AUTH_EXPIRED`). The spec doc is corrected via this decision log; the test `downloadFile (error paths) > 401 → FreeloApiError AUTH_EXPIRED exit 3` asserts exit 3.

**Alternatives considered:**
- Override the FreeloApiError mapping in the download leaf to force exit 4. Rejected — would diverge from every other read command's contract (R03/R16/R21/R26 all surface 401 as exit 3).
- Refactor `FreeloApiError.fromResponse` to map 401 → exit 4. Out of scope; would break every existing 401 test.

**Rationale:** The architecture.md §Exit codes documents `3 auth error (missing/expired credentials)`. The spec doc's "exit 4" was a copy-paste error. The implementation inherits from the shared error class — the right thing happens automatically.
