# Decision 6 — `--at` value canonicalized to second-precision UTC before sending

**Run:** 2026-04-28-2050-r19.5-time-start-backdate
**Phase:** spec
**Agent:** orchestrator (architect role)

**Question:** Forward the user's literal `--at` string as-is, or canonicalize to UTC?

**Decision:** Canonicalize via `new Date(t).toISOString().slice(0, 19) + 'Z'`.

**Alternatives considered:**
- Forward as-is (preserves user's tz offset on the wire) — mixed tz handling on the server side is a surprise vector; tests and fixtures get harder.
- Canonicalize but keep millis (`.500Z`) — the existing R19 status endpoint emits second-precision `date_reported` in its responses; matching that on the request side keeps round-trip diffs clean.

**Rationale:** One canonical wire shape is simpler for fixtures, agents, and Freelo's audit logs. Users can still pass any tz; the CLI does the right thing.
