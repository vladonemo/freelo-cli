# Decision 5 — NDJSON keys: `to_tasklist` / `to_project` (not `_id`-suffixed)

**Run:** 2026-04-27-R12.5-tasks-move-batch
**Phase:** 2 (spec) — architect
**Agent:** orchestrator (architect role)

**Question:** Per-line NDJSON keys for the destination — `to_tasklist` or
`to_tasklist_id`? `to_project` or `to_project_id`?

**Decision:** Short form. `id`, `to_tasklist`, `to_project`.

**Alternatives considered:**

- **`_id`-suffixed**: `to_tasklist_id`, `to_project_id`. Matches the **envelope
  output** (`data.to_tasklist_id`, `data.to_project_id`). Rejected: stdin shape
  and envelope shape need not be symmetric.

**Rationale:** R09 uses `due` (not `due_at`), `worker` (not `worker_id`),
`priority` (not `priority_level`). R11 uses `id` (not `task_id`). Short form is
the established stdin convention for this CLI. Symmetry with envelope keys is
nice-to-have but not load-bearing — agents already do `{...}` shape transforms,
so a 3-character difference doesn't move the needle.
