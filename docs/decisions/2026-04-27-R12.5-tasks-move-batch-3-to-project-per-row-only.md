# Decision 3 — `--to-project` is per-row only in `--stdin`; reject as global flag

**Run:** 2026-04-27-R12.5-tasks-move-batch
**Phase:** 2 (spec) — architect
**Agent:** orchestrator (architect role)

**Question:** When `--stdin` is set, can a command-line `--to-project <id>` apply
globally (same assertion for every row)? Or must `to_project` only appear per-row
inside the NDJSON?

**Decision:** Per-row only. A command-line `--to-project` while `--stdin` is set
fails fast with `VALIDATION_ERROR` (exit 2) at flag-validation time.

**Alternatives considered:**

- **Allow both** (per-row overrides global) — rejected: ambiguous merge rule. If
  `--to-project 42` is on the command and a row has `"to_project": 99`, which is
  intended? Either choice is wrong half the time.
- **Global only** — rejected: defeats the per-row power. Different rows may
  legitimately target different projects.

**Rationale:** Run-config default said "per-row only, follow R12 precedent". R12's
`--to-project` is a single-task assertion (post-hoc). Batch input fundamentally
implies different per-row destinations; making the assertion global contradicts
that. Hard-reject is the cleanest UX — agents see the error, fix the input, retry.
