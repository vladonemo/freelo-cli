# Decision 1 — New `parseIsoTimestampFlag` helper, not reuse of `parseDateFlag`

**Run:** 2026-04-28-2050-r19.5-time-start-backdate
**Phase:** spec
**Agent:** orchestrator (architect role)

**Question:** Should `--at` reuse the existing `parseDateFlag` from `tasks create` / `tasks edit` / `tasks list` / `subtasks add` / `comments list`?

**Decision:** No. Introduce a new helper `parseIsoTimestampFlag` in `src/lib/iso-timestamp.ts`.

**Alternatives considered:**
- Reuse `parseDateFlag` as-is — date-only regex (`YYYY-MM-DD`); forbids hour-of-day backdating which is the whole feature.
- Extend `parseDateFlag` with a `mode` arg — adds a footgun on five existing call sites that all expect date-only semantics.
- Inline the logic in `time/start.ts` — R20 will likely reuse it for `time edit --at`.

**Rationale:** New helper, narrow surface, single-responsibility. Roadmap line said "reuse the helper" but actual semantics differ; keeping the existing date-only helper unchanged preserves five callsites' behavior with no refactor risk.
