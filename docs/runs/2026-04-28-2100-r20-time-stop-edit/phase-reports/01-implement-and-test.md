## Retry record

**Iteration 1.** Initial implementation used Commander's negatable `--no-task` form for `time edit`. Tests revealed Commander stores `--no-<flag>` as the inverted value of the same option (`opts.task = false`), which clobbers the captured `--task <id>` when both are passed. Mutex check failed: `--task 4567 --no-task` produced `task: false`, mutex never tripped, and the action attempted to use `false` as a task id (network error → exit 5). Two related test cases also failed because `opts.noTask` was always `undefined` on negatable storage.

**Fix.** Renamed `--no-task` to `--clear-task` (positive name, independent option storage). Updated:

- `src/commands/time/edit.ts` (option declaration + `opts` type + mutex check + empty-edit hint).
- `test/commands/time/edit.test.ts` (8 occurrences of `--no-task` → `--clear-task`).
- `docs/specs/0032-time-stop-edit.md` (decision 3 + scattered references).
- `docs/runs/.../decisions/03-task-no-task-mutex.md` (updated rationale).

**Iteration 2.** All R20 tests pass (54/54).
